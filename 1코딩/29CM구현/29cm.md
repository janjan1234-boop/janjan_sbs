# 29CM 상단 메뉴 스타일

- 측정 페이지: https://www.29cm.co.kr/
- 측정 대상: `ul.flex.items-center.gap-16.desktop\:gap-18` (마이페이지·좋아요·장바구니·로그인/회원가입을 담은 목록)
- 측정 조건: Playwright 브라우저, 1920 × 945px 데스크톱 뷰포트, 2026-11-02

| 항목 | 측정값 |
| --- | --- |
| 실제 넓이 | **316.95px** (`getBoundingClientRect()` 기준 316.953px) |
| 실제 높이 | **28px** |
| 위치 | 왼쪽 1540.05px, 위 40px |
| 바깥 여백 (`margin`) | 상·우·하·좌 모두 `0px` |
| 안쪽 여백 (`padding`) | 상·우·하·좌 모두 `0px` |
| 자식 요소 간격 (`gap`) | **18px** (`desktop:gap-18`; 기본 `gap-16`은 16px) |
| 배치 | `display: flex`, 수직 가운데 정렬 (`align-items: center`) |
| 글꼴 | `29CM Editorial` 우선, 시스템 글꼴 대체 |
| 폰트 크기 | **16px** |
| 폰트 두께 | **200** (`font-extralight` 상속) |
| 줄 높이·자간 | `24px`, `normal` |
| 폰트 색상 | `rgb(0, 0, 0)` / `#000000` |
| 배경·테두리 | 배경 투명, 테두리 없음 |

이 값은 **목록(`ul`) 자체의 계산 스타일**이다. 내부 버튼은 별도 스타일을 가질 수 있다. 예를 들어 `로그인/회원가입` 버튼의 글자는 11px, 두께 400, 색상 `#1F1F1F`이다. 현재 보이는 항목 4개의 너비 합계는 약 262.95px이며, 사이의 간격 3개(총 54px)를 더하면 목록 너비 약 316.95px이 된다.

## 직접 작성한 `.tophead-right`와 정렬·아이콘 크기가 다른 이유

1. 원본 29CM의 아이콘은 화면에서 **18 × 18px**로 표시된다. 현재 저장한 SVG에는 `width="24" height="24"`가 있어, CSS로 크기를 지정하지 않은 `<img>`는 24 × 24px로 표시된다.
2. 원본은 아이콘과 글자를 감싼 `<a>`에 `display: flex`, `align-items: center`, `gap: 4px`를 적용한다. 현재 CSS의 `.tophead-right > ul > li`에는 `align-items: center`만 있고 `display: flex`가 없으므로 이 속성이 정렬에 영향을 주지 않는다.
3. 원본의 데스크톱 `ul` 항목 간격은 **18px**인데, 현재 `.tophead-right > ul`에는 **14px**이 적용되어 있다.
4. 원본은 로그인 버튼까지 같은 `ul`의 마지막 `li`에 넣는다. 현재 HTML에서는 로그인 버튼이 `ul` 밖에 있어서, 마지막 항목과 버튼 사이에는 `.tophead-right`의 별도 간격이 적용된다.
5. 원본의 아이콘 옆 글자는 **10px / 줄 높이 12px**이다. 현재 `li`에 지정한 `height: 28px`과 기본 인라인 `<a>`의 줄 배치도 위치 차이를 만든다. `font { ... }` 규칙은 `<font>` 태그에만 적용되므로 페이지의 기본 글꼴을 지정하려면 `body { ... }`를 사용해야 한다. 원본의 글꼴은 `29CM Editorial`이며 현재 사용한 Pretendard와 글자 폭이 다를 수 있다.

### 맞추는 방법

```css
.tophead-right > ul {
  display: flex;
  align-items: center;
  gap: 18px;
}

.tophead-right > ul > li {
  height: auto;
}

.tophead-right > ul > li > a {
  display: flex;
  align-items: center;
  gap: 4px;
  font-size: 10px;
  line-height: 12px;
  font-weight: 200;
}

.tophead-right > ul > li > a > img {
  display: block;
  width: 18px;
  height: 18px;
}
```

로그인 버튼도 `ul`의 마지막 `li`에 옮기면 모든 항목에 같은 `18px` 간격이 적용된다. 버튼 자체의 글자와 테두리 스타일은 별도로 유지하면 된다.

## 데스크톱 GNB `nav` 스타일

- 대상: `nav.hidden.w-full.min-w-0.flex-col.desktop\:flex.desktop\:flex-1.desktop\:gap-26`
- 측정 조건: Playwright 브라우저, 1920 × 945px 데스크톱 뷰포트

| 항목 | 측정값 |
| --- | --- |
| 실제 넓이·높이 | **1809 × 102px** |
| 위치 | 왼쪽 `48px`, 위 `92px` |
| 너비·최소 너비 | `width: 1809px` (`w-full`), `min-width: 0px` |
| 배치 | `display: flex`, `flex-direction: column`, `flex: 1 1 0%` |
| 바깥 여백 (`margin`) | 상·우·하·좌 모두 `0px` |
| 안쪽 여백 (`padding`) | 상·우·하·좌 모두 `0px` |
| 자식 간격 (`gap`) | **26px** (세로·가로 계산값 모두 26px) |
| 글꼴 | `29CM Editorial` 우선, 시스템 글꼴 대체 |
| 폰트 크기·두께 | **16px / 800** (`extrabold`) |
| 줄 높이·자간 | `24px` / `normal` |
| 폰트 색상 | `rgb(0, 0, 0)` / `#000000` |
| 배경·테두리 | 배경 투명, 테두리 없음 |

두 직계 자식의 높이는 각각 **48px**과 **28px**이며, 사이 간격 **26px**을 더해 전체 높이 **102px**이 된다. 위의 16px·두께 800은 `nav`의 계산 스타일이다. 내부 메뉴 링크에는 별도의 글자 크기와 두께가 적용된다. 화면 너비가 달라지면 실제 넓이와 높이도 달라질 수 있다.

## 작성 중인 `.topbar`와 원본 GNB의 높이·여백 차이

1920 × 945px 화면에서 원본 `gnb-content-container`의 실제 높이는 **214px**이다. 현재 작성 중인 `.topbar`는 `height: 248px`로 고정되어 있다.

| 위치 | 작성 중인 CSS | 원본 29CM |
| --- | ---: | ---: |
| 위쪽 안쪽 여백 | 40px | 40px |
| 상단 헤더 높이 | 28px | 28px |
| 상단 헤더와 큰 메뉴 사이 | 20px | 24px |
| 큰 메뉴 높이 | 48px | 48px |
| 큰 메뉴와 아래 메뉴 사이 | 30px | 26px |
| 아래 메뉴 높이 | 28px | 28px |
| 아래쪽 안쪽 여백 | 20px | 20px |

작성 중인 요소들의 높이 합계는 `40 + 28 + 20 + 48 + 30 + 28 + 20 = 214px`이다. 그런데 `.topbar`의 높이를 248px로 고정해 **아래에 34px의 빈 공간**이 남는다. 첫 번째 메뉴 간격이 4px 작고 두 번째 간격이 4px 커서, 아래 메뉴의 시작 위치는 우연히 원본과 같지만 큰 메뉴는 원본보다 4px 위에 놓인다.

1920px 화면 기준으로 맞추려면 다음 값을 사용한다.

```css
.topbar { height: auto; }
.topgnb { margin-top: 24px; }
.topnav { margin-top: 26px; }
```

원본은 화면 너비에 따라 내부 메뉴의 배치와 전체 높이가 달라진다. 앞에서 측정한 1365px 화면의 원본 높이는 **248px**이므로, 모든 화면에서 높이를 248px로 고정하면 1920px 화면과 차이가 난다.

## 원본 29CM 데스크톱 푸터

- 측정 페이지: https://www.29cm.co.kr/
- 대상: `footer.desktop\:mp-24.flex.flex-col.gap-12.bg-gray-200.px-16.pb-10.pt-20.desktop\:bg-transparent.desktop\:px-48.desktop\:pb-48`
- 측정 조건: Playwright 브라우저, 뷰포트 1669 × 945px. 아래 값은 브라우저의 `getComputedStyle()` 및 `getBoundingClientRect()` 결과다. 화면 너비와 콘텐츠에 따라 푸터 크기 및 줄바꿈은 달라질 수 있다.
- 실제 푸터 크기: **1654 × 444.89px**. 뷰포트 너비와의 15px 차이는 스크롤바 영역이다.
- 모바일 390px에서는 이 푸터 DOM이 나타나지 않고 별도의 검은색 푸터(`footer.block.bg-black...`)가 렌더링된다. 따라서 아래 값은 데스크톱 푸터 기준이다.

### 이미지와 아이콘

푸터 안에 `<img>`나 CSS 배경 이미지는 없다. 소셜 링크의 인라인 SVG 4개를 원본 DOM에서 추출해 `image` 폴더에 저장했다.

| 원본 아이콘 | 저장 파일 | 원본 표시 영역 |
| --- | --- | --- |
| Instagram | `image/footer-instagram.svg` | 검은 원형 링크 30 × 30px |
| YouTube | `image/footer-youtube.svg` | 검은 원형 링크 30 × 30px |
| Apple App Store | `image/footer-apple.svg` | 검은 원형 링크 30 × 30px |
| Google Play | `image/footer-google-playstore.svg` | 검은 원형 링크 30 × 30px |

SVG의 `viewBox`는 모두 `0 0 24 24`이고 흰색 계열 도형(`fill="#fff"`, 투명도 0.9)을 사용한다. 링크는 검은 배경에 `padding: 6px`, 원형 모서리이며 아이콘 링크 간격은 8px이다. 실제 Instagram SVG의 렌더링 크기는 18 × 24px로, 링크의 flex 레이아웃 안에서 가로가 줄어든다.
